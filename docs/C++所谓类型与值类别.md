# C++类型和值类别
---

先直接丢结论，类型解读一个变量这块内存的方法，以及判别它是一个什么样的标签。

值类别是表达式产生的，有左值，右值，纯右值，将亡值等分类。

类型推导时，指针归为类型。而引用的 & 符号则用来判别其值类型。
类型推导会抹除 const (非底层const) 和引用(无论左值引用右值引用)的信息，但不会抹除本身类型和指针，因为指针也算类型。

---

先从类型推导讲起：
```cpp
int
int&
int&&

const int
const int&
const int&&

int*
const int*
int* const
```
如果我现在用一个 `auto` 去接收上面的变量，最终推导出来会是什么样的？
先给结论在一个个解释，`auto` 接收以后得到如下类型：
```cpp
int
int
int

int
int
int

int*
const int*
int*
```
是否非常的神奇？首先先来讲 `auto` 本身，`auto` 本身的类型推导是**值语义**的。对于 `int&` 和 `int&&` 来说，它们在 C++ 中都属于 **别名**，当你去使用它时，和使用一个类型为 `int` 的那个变量本身没有什么区别，也就是引用管的是值本身，而不能视为一个类型。

所以当 `auto` 无论接收 `&` 还是 `&&`，都会将其抹去。既然已经抹去了，最后的推导就是简单的值复制，既然值都已经复制了，我修改复制之后的变量，对原有的变量没有任何影响，那么这里的 `const` 也变得不再重要了，因此可以一并抹去。

再来看 `int*`，`int*` 是一个实打实的类型，指针类型。因此使用 `auto` 去接收是会推导出完整的 `int*`。但为什么 `const int*` 完整推导出来了，但 `int* const` 退化成 `int*` 了呢？这是因为 `const` 有顶层与底层之分，`const int*` 称为 **顶层 const**，它常量化的不是指针本身，而是指针指向的那个值，也就是 `(const int)*`，因此这个时候 `auto` 在推导的时候，必须保证复制过来的这个指针里面的值也不能修改才能保证常量语义。

而 `int* const`，可以形式上视作 `int (* const)`。它修饰的是这个指针本身的指向不能被更改，这不就和我们上面说的值复制是一样的吗？既然指针的值已经复制过来了，改变指向对原来的变量没有影响，所以保持 `const` 没有意义，故可以省略。

---

再来看更复杂的例子：用 `auto&` 接收会怎么样？`auto&` 代表我们希望以 **引用语义** 来接收值，这时候上面的例子就会变为：
```cpp
int&
int&
int&

const int&
const int&
const int&

int *&
const int*&
int* const&
```
这个时候代表你希望得到原本变量的别名，那么原来变量的一切修饰符都应当被继承，因此此时这个新变量等同于原变量。

---
最后再来看一个最神奇的 `auto&&`，这个叫万能引用，注意我们的 `auto&` 无法接收右值。 `auto&&` 可以接收任意类型与任意值类别。

它和 `auto&` 唯一区别就在于，当接收一个右值时，它会推导为 `&&` 类型。

---
